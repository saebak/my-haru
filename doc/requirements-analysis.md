# 요구사항 분석

## 1. 분석 목적

`requirements.md`를 구현 가능한 작업 단위로 해석하고, 현재 Phase 1 구현과 목표 제품 사이의 차이, 우선순위, 의존성을 명확히 한다. 이 문서는 요구사항을 대체하지 않으며 충돌 시 `requirements.md`가 우선한다.

## 2. 제품 범위 해석

제품은 다음 네 단계로 확장한다.

1. 개인 사용 MVP: 한 기기에서 할 일과 반복 습관을 오프라인으로 관리한다.
2. 계정·동기화: 인증을 확정하고 앱 삭제 후 복원, 서버 백업과 다중 기기 동기화를 제공한다.
3. 알림·사용성: 알림과 통계가 실제 습관 유지에 도움이 되는지 검증한다.
4. 출시·수익화: 앱인토스 검수, 배너 광고, 분석과 정산을 운영한다.

Phase 1 로컬 MVP의 CRUD, 반복 일정, 목록 탐색, IndexedDB 저장과 로컬 백업이 구현돼 있다. Phase 2의 첫 단계로 앱인토스 익명 식별과 Supabase 전체 스냅샷 백업·복원도 배포했다. 로컬 저장이 항상 선행되며 클라우드 장애는 핵심 사용 흐름을 막지 않는다. 증분 동기화·충돌 UI와 실제 Android·iOS 회귀 검증은 남아 있다.

## 5. 데이터 모델 해석

### Todo

일반 할 일과 반복되는 할 일의 내용·반복 정의를 함께 가진다. `type`은 `one_time | recurring`으로 저장 방식을 나타내고 `category`는 `todo | habit`으로 제품 의미를 나타낸다. 따라서 `category=todo, type=recurring`인 반복 할 일을 지원한다. 반복 Todo는 `seriesId`, `revision`, 빈도·간격·요일·시작일·종료일을 가진다. 일반 Todo의 완료 상태 변경은 `status`와 `completedAt`을 하나의 원자 작업으로 저장한다.

### TodoRecord

반복 Todo series와 대상 날짜별 수행 상태를 저장한다. 같은 `seriesId + targetDate` 조합은 하나만 존재한다. 이 날짜만 수정·삭제하는 경우 같은 레코드의 override와 `hidden`을 사용한다. 조회 시 날짜에 유효한 Todo revision과 결합하므로 Todo 분할 시 record를 이동하지 않는다.

### Reminder

Phase 3에서 구현한다. 대상, 예약 시각, 시간대, 활성 여부와 발송 상태를 분리해 완료·삭제·시간 변경 시 예약을 취소하거나 갱신할 수 있게 한다.

## 7. 주요 위험

### 날짜와 시간대

Phase 1은 `Asia/Seoul`의 달력 날짜와 `dueTime` 문자열로 계산·정렬하고 기기 시간대 변경 시 기존 값을 재해석하지 않는다. UTC 실제 시각 변환과 DST gap/fold 정책은 알림을 구현하는 Phase 3에서 결정한다.

### 로컬 저장소 보존 한계

프로덕션 데이터는 schema version 2의 IndexedDB에 먼저 저장하고 정적 목업의 `localStorage`는 이전하지 않는다. QR 테스트와 출시 환경은 origin이 달라 로컬 데이터를 공유하지 않는다. 같은 앱인토스 사용자로 식별되면 서버 스냅샷을 복원하지만, 첫 동기화 전 데이터와 토스 외 배포판의 계정 연결은 자동 복원 대상이 아니다.

### 서버 백업 한계

현재는 변경마다 전체 Todo·TodoRecord 스냅샷을 전송한다. 초기 사용자 규모에서는 단순성과 복구 안전성을 우선한 선택이지만 데이터가 커지면 전송량과 쓰기 비용이 증가한다. 다음 단계에서 outbox·멱등 operation·증분 pull을 추가하고 저장 실패율과 복원 성공률을 계측한다.

### 반복 수정

이 날짜부터 이후 수정은 대상 Todo 종료, 이후 활성 revision 정리와 같은 `seriesId`의 `maxRevision + 1` Todo 생성으로 모델링한다. 이 날짜만 수정은 TodoRecord override로 처리하며 대상 날짜 이전 Todo와 record는 수정하지 않는다.

### 외부 SDK 의존

알림·로그인·광고 API와 정책은 변경될 수 있다. SDK 호출을 UI와 도메인 코드에 직접 퍼뜨리지 말고 어댑터에 모은다.

### 범위 확대

공유, 캘린더 연동, AI 추천, 위젯, 결제는 초기 제외 범위다. 핵심 기능과 리텐션을 검증하기 전에는 구현하지 않는다.

## 8. 단계별 완료 판단

### 개인 사용 MVP

- 한 기기에서 생성·완료·반복 기록이 재실행 후 유지됨
- 반복 경계와 백업·복원 테스트 통과
- 네트워크 없이 핵심 기능 사용 가능
- 데이터 유실 가능성이 있는 알려진 결함 없음

### 계정·서버 동기화

- 인증 방식을 확정하고 사용자별 데이터 격리 검증
- 기존 IndexedDB 데이터를 동일 UUID로 최초 업로드
- 앱 삭제·저장소 초기화 후 서버 데이터 복원
- 오프라인 재전송, 충돌, 삭제 동기화 검증

### 알림·사용성

- 실제 토스 앱에서 동의·철회·수신·딥링크 검증
- 통계와 알림을 1~2주 직접 사용해 효용 확인

### 출시·광고

- 테스트·운영 광고 설정 분리
- 광고 실패가 핵심 기능에 영향 없음
- 앱인토스 기능·디자인·보안 검수 통과
- 운영 지표와 정산 확인 가능
