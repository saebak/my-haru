## 2026-09-10 — 독립 설계 감사 후 Phase 1 모델 확정

### 확정

- 별도 Habit·RecurrenceRule 없이 `Todo.type = one_time | recurring`으로 통합
- 반복 정의와 콘텐츠는 Todo가 소유하고 날짜별 수행·단일 날짜 override는 TodoRecord가 소유
- 반복 수정·삭제 범위는 `이 날짜만`, `이 날짜부터 이후` 두 가지로 단순화
- 이후 수정은 기존 Todo를 전날 종료하고 같은 `seriesId`의 새 revision Todo를 생성
- 통계와 알림은 Phase 3으로 이동
- Phase 1은 `Asia/Seoul`의 `dueDate/targetDate + dueTime` 문자열로 정렬하고 DST는 처리하지 않음
- Phase 2 인증·동기화·Supabase 상세 설계와 기존 API·migration을 동결

### 설계 보완

- IndexedDB v1의 Todo·TodoRecord 저장 레코드, unique 인덱스와 불변식 명시
- migration의 abort, blocked, versionchange와 미래 DB version 처리 규칙 추가
- 백업 전체 검증과 단일 transaction 전체 교체 알고리즘 명시
- 날짜 단일 수정에서 값 제거와 미수정을 구분하도록 `overrides` 객체의 속성 존재 여부 사용
- TodoRecord의 논리 키를 `[seriesId,targetDate]`로 변경해 revision 분할 후에도 기록을 재귀속하지 않도록 보완
- 동결된 Supabase README에서 실제 적용·RPC 실행 절차 제거
- Phase 1 실행 절차에서 `.env.local` 필수 설정 제거
- 과거 revision에서 이후 수정·삭제할 때 series suffix 전체를 원자적으로 정리하고 새 revision은 max + 1로 생성
- 이후 삭제 시 대상일 이후 TodoRecord도 같은 transaction에서 소프트 삭제
- 소프트 삭제 TodoRecord 논리 키 재사용과 실행 취소의 서로 다른 복원 규칙 명시

- 2026년 9월 18~21일에 각각 4개 일정과 1·2·3·4개 완료 상태를 넣어 캘린더의 25% 새싹, 50% 잎새, 75% 나무, 100% 숲 단계를 직접 비교할 수 있게 했다. 데이터 생성용 임시 코드는 실행 후 제거했다.
- UUID 대체 경로의 버전·variant 비트와 문자열 형식을 검증하는 저장소 단위 테스트를 추가했다.

## 2026-09-17 — 토스 익명 식별·Supabase 백업 기반 구현

- 앱은 IndexedDB를 먼저 표시하고 `User.getAnonymousKey.isSupported()`인 토스 WebView에서만 사용자 식별을 시도하도록 추가했다. 브리지나 네트워크 장애 시 로컬 CRUD는 계속 동작한다.

- 검증: ESLint 통과, Vitest 8개 파일 48개 테스트 통과, TypeScript와 Vite 프로덕션 웹 빌드 통과. 앱 초기 청크는 69.26kB(gzip 21.49kB)로 줄었고 앱인토스 SDK 지연 청크는 678.04kB(gzip 190.91kB)여서 전체 빌드의 500kB 경고는 남아 있다.

### mTLS 없는 초기 백업 흐름으로 전환

- 사용자 결정에 따라 별도 mTLS 검증 서버가 없어도 `getAnonymousKey()` 결과를 계정 증명값으로 받아 즉시 HMAC-SHA256 처리하도록 변경했다. 원문 키를 DB에 저장하지 않는 원칙과 공급자 독립 `account_id` 구조는 유지했다.
- 익명 키는 16~512자로 제한하고, 선택적 검증 서버 URL이 나중에 설정되면 기존 코드 경로에서 먼저 토스 유효성 검증을 수행하도록 확장 지점을 유지했다.
- 이 방식은 키 유출 시 재사용 위험이 있으므로 Todo 백업 같은 저위험 데이터에만 사용하고, 결제·포인트·민감정보 도입 전에 mTLS 검증을 추가하도록 요구사항과 설계 문서를 갱신했다.
- 전체 검증: ESLint, Vitest 8개 파일 48개 테스트, TypeScript와 Vite 프로덕션 웹 빌드 통과. 기존 앱인토스 SDK 지연 청크의 500kB 경고는 남아 있다.
- `MY-HARU`의 `account-sync` Edge Function을 v2로 재배포했고 상태 `ACTIVE`, `verify_jwt=false`를 확인했다. 실제 토스 익명 키를 사용하는 최초 계정 생성·복원은 새 앱 번들을 Sandbox에서 실행해 확인해야 한다.
